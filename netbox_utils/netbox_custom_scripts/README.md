# Export Active DNS Zones
# bind_config_generator.py

## Overview

**Export Active DNS Zones** is a NetBox **Custom Script** that exports all *active* DNS zones from the NetBox DNS plugin into BIND-compatible configuration include files.

The script separates zones by DNS view and generates:

- **Internal view zones**
- **External (split-horizon) view zones**

After generating the configuration files, it safely reloads `named` to apply the changes.

This script is designed for environments where **NetBox is the source of truth for DNS zones** and BIND is managed via generated include files.

---

## What This Script Does

1. **Temporarily changes ownership** of the BIND export directory to `netbox:netbox`
2. **Queries NetBox DNS zones** with `status = active`
3. **Separates zones by view**
   - `internal` → internal zones config
   - `external` → split-horizon zones config
4. **Writes BIND `zone {}` stanzas** to config include files
5. **Restores ownership** to `bind:bind`
6. **Reloads BIND** using `bind_reconfig.sh`

---

## Generated Files

| View | Output File |
|----|----|
| Internal | `/services/bind/config/active_zones.conf` |
| External / Split | `/services/bind/config/external_zones.conf` |

Each zone entry is written in standard BIND format:

```conf
zone "example.org" {
  type master;
  file "/services/bind/zonefiles/internal/example.org";
  notify yes;
};

# NetBox DNS Export Scripts

This directory contains NetBox **Custom Scripts** used to export DNS data from the NetBox DNS plugin into **BIND-compatible configuration files and zone files**.

These scripts assume **NetBox is the authoritative source of DNS truth** and that BIND configuration and reloads are automated from generated files.

---

## Installation

1. Place these scripts in your NetBox `SCRIPTS_ROOT`
2. Restart NetBox services:
   ```bash
   systemctl restart netbox netbox-rq
   ```
3. Navigate to **Customization → Scripts** in the NetBox UI

---

## Export Active DNS Zones

### Overview

**Export Active DNS Zones** exports all *active* DNS zones from NetBox into BIND include configuration files, separated by DNS view.

It generates configuration stanzas for:
- **Internal zones**
- **External (split-horizon) zones**

After writing the configuration files, the script reloads BIND to apply the changes.

---

### What This Script Does

1. Temporarily changes ownership of the BIND directory to `netbox:netbox`
2. Queries NetBox DNS zones with `status = active`
3. Separates zones by DNS view:
   - `internal`
   - `external`
4. Writes BIND `zone {}` stanzas to include files
5. Restores ownership to `bind:bind`
6. Reloads BIND using `bind_reconfig.sh`

---

### Generated Files

| View | Output File |
|----|----|
| Internal | `/services/bind/config/active_zones.conf` |
| External / Split | `/services/bind/config/external_zones.conf` |

Example zone entry:

```conf

  type master;

  notify yes;

```

---

### Requirements

- NetBox with **netbox-dns-plugin**
- Zones must be:
  - `status = active`
  - Assigned to a view named `internal` or `external`
- BIND directory structure under `/services/bind`
- NetBox user permitted to run `sudo` commands

---

### Script Metadata

| Field | Value |
|----|----|
| Name | Export Active DNS Zones |
| Commit Default | Disabled |
| Modifies NetBox Data | No |

> The `commit` flag does not alter behavior. File writes and reloads always occur.

---

### Permissions & Security

Required sudo rules:

```sudoers
netbox ALL=(root) NOPASSWD: /bin/chown -R netbox:netbox /services/bind
netbox ALL=(root) NOPASSWD: /bin/chown -R bind:bind /services/bind
netbox ALL=(root) NOPASSWD: /services/bind/scripts/bind_reconfig.sh
```

---

### Notes & Caveats

- Only `internal` and `external` views are processed
- Zone files themselves are not generated by this script
- Assumes BIND reloads are handled by `bind_reconfig.sh`

## Zone Exporter

### Overview

**Zone Exporter** exports DNS zones and records from NetBox into full **BIND zone files**, organized by DNS view.

Zone files are fully regenerated from NetBox and written directly into the BIND zonefile tree. After export, BIND is reloaded to apply changes.

---

### What This Script Does

1. Temporarily changes ownership of the BIND directory to `netbox:netbox`
2. Deletes existing exported zone files (destructive)
3. Iterates through all DNS views
4. Exports all **active zones** per view
5. Renders zone files using an embedded Jinja2 template
6. Restores ownership to `bind:bind`
7. Reloads BIND using `bind_reconfig.sh`

---

### Export Location

Zone files are written to:

```
/services/bind/zonefiles/<view>/<zone_name>
```

Example:

```
/services/bind/zonefiles/internal/example.org
/services/bind/zonefiles/external/example.org
```

---

### Zone File Format

Zones are rendered using a hard-coded Jinja2 template:

```zone
;
; Zone file for zone example.org [internal]
;

$TTL 3600

www                             IN A       192.0.2.10
```

- `$TTL` comes from `zone.default_ttl`
- Only **active records** are exported
- Record fields are padded for readability

---

### Script Metadata

| Field | Value |
|----|----|
| Name | Zone Exporter |
| Commit Default | Enabled |
| Modifies Filesystem | Yes (destructive) |

> The `commit` flag does not alter behavior — this script always writes files and reloads BIND.

---

### Destructive Behavior (Important)

**Existing zone files are deleted** before export.

This ensures filesystem state matches NetBox exactly.

Do **not** run this script if:
- Zone files are manually maintained
- Out-of-band zones exist

---

### Requirements

- NetBox with **netbox-dns-plugin**
- DNS views defined in NetBox
- Jinja2 installed
- BIND directory layout under `/services/bind`

---

### Permissions & Sudo Requirements

```sudoers
netbox ALL=(root) NOPASSWD: /bin/chown -R netbox:netbox /services/bind
netbox ALL=(root) NOPASSWD: /bin/chown -R bind:bind /services/bind
netbox ALL=(root) NOPASSWD: /services/bind/scripts/bind_reconfig.sh
```

---

## Typical Workflow

1. Manage zones and records in NetBox
2. Run **Zone Exporter** to generate zone files
3. Run **Export Active DNS Zones** to generate include configs
4. BIND reloads and serves updated zones
